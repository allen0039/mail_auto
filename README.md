# Mail Auto · 0.4.1

Go 编写的个人多邮箱工作台，支持 IMAP 自动同步、原邮箱文件夹分类、归档、移入回收站、恢复和受控任务。通过 MCP 挂载给 Codex / ChatGPT 使用，不接入 AI API。

MCP 默认关闭，域名可暂留空。「整理与 MCP」页面可直接保存公开 HTTPS 地址和开关、检测连接并复制 Codex / ChatGPT 配置，无需修改启动参数。分类会把邮件移动到**原邮箱中的真实文件夹**，邮箱网页和手机端同步后可见。支持在原邮箱创建文件夹；归档与回收站独立可选。

新增「整理规则」「定时与任务」「TG 通知」：可视化规则、试运行、观察/执行授权；每项任务可选仅手动、内置定时或外部 MCP，也可跟随全部启用规则或绑定指定规则版本。Telegram 可选仅失败、有变更或每次结束通知。AI 由外部 MCP 客户端触发，服务端不接入模型 API。[使用说明](docs/automation-guide.md)。

远端整理逐账号默认关闭。支持原生 MOVE + UIDPLUS，也支持 UIDPLUS 的确认复制后定向移除兼容路径。不会发送全局 EXPUNGE，不提供永久删除。配置与使用见 [MCP 接入指南](docs/mcp-setup.md)，测试边界见 [0.4.1 验收记录](docs/acceptance-0.4.1.md)。

支持 QQ、网易（163 / 126 / yeah.net）、iCloud 的 IMAPS 接入；此前已验证单个网易账号 13 个文件夹、1,730 条元数据只读同步。QQ、iCloud 和真实远端写入仍待专用测试邮件验证。

## 快速开始

镜像：[`allen0039/mail-auto`](https://hub.docker.com/r/allen0039/mail-auto)，已发布版本包含 `0.4.1` 和 `latest`。镜像构建支持 Linux amd64 / arm64，标准部署无需 `.env`。 发布时版本号从上一个已发布标签逐次递增，镜像、Compose、界面、MCP 和 Git 标签使用同一版本号。

在运行 Docker 的主机执行：

```bash
docker compose pull
docker compose up -d --no-build
docker compose exec app mail-auto bootstrap show
```

默认仅监听宿主机 `127.0.0.1:8080`。本机部署打开 <http://127.0.0.1:8080>；远程部署可使用 SSH 转发（将 `user@server` 替换为自己的主机）：

```bash
ssh -L 8080:127.0.0.1:8080 user@server
```

使用命令显示的随机用户名和临时密码登录，**同时修改用户名和密码**，然后重新登录。公网访问请配置 HTTPS 反向代理、精确的 `public_url` 和安全 Cookie，见 [配置文档](docs/configuration.md)。

- 临时密码有效 24 小时，首次成功登录后立即失效；首次设置会话有效 30 分钟。
- 新用户名为 3–64 位英文字母、数字、点、下划线或横线；新密码至少 12 个字符，最多 256 字节。
- 常规日志不输出账号密码，`bootstrap show` 仅供宿主机管理员主动查看；请不要把输出粘贴到公开日志。
- 正式登录后可在「系统设置」修改用户名或密码，需验证当前密码；新密码留空表示仅修改用户名。保存后所有设备退出，使用更新后的凭据重新登录。
- 正常重启与容器重建保留管理员和主密钥。丢失设置会话、临时密码到期或忘记正式密码时，执行下方恢复命令。

添加邮箱后会自动连接和同步，可使用「连接诊断」检查访问范围，「同步邮件」仍可手动重新扫描。授权码经加密保存，读取正文不会改变已读状态。

## 当前功能

| 能力 | 当前行为 |
| --- | --- |
| 管理员 | 随机初始账号、一次性临时密码、强制修改、系统设置中修改账号/密码、服务端会话、退出与本地恢复 |
| HTTP 防护 | CSRF / Origin 校验、登录限流、哈希验证并发上限、安全响应头、请求大小限制 |
| 凭据 | Argon2id 密码哈希，AES-256-GCM 字段加密，独立密钥卷，外部只读 secret |
| 邮箱 | 最多 10 个账号；支持编辑已有连接及更新授权码；固定提供商主机白名单、TLS 1.2+，默认全部可读取文件夹，可选限定范围 |
| 同步 | 后台自动增量校对；支持收件箱优先 IDLE 推送及全文件夹周期校对；新增/删除/移动/已读状态自动更新，手动全历史同步仍可用 |
| 搜索 | 本地元数据：账号、文件夹、主题/发件人、发件人、接收日期（北京时间）、未读、分页 |
| 正文 | 按需读取；原始邮件不超过 4 MiB；中文解码、纯文本优先、HTML 转文本；输出不超过 64 KiB |
| 附件 | 只显示名称、MIME 类型与编码体积；不下载和解析附件内容 |
| 运维 | `/healthz`/`/readyz` 健康检查、脱敏审计、一致性 SQLite 备份、密钥匹配检查、优雅退出 |
| 整理 | 在原邮箱创建文件夹及分类移动，冻结预览、异步任务、幂等、逐项结果、停止剩余项、核验未知结果、恢复与补偿撤销 |
| MCP | 官方 Go SDK、Streamable HTTP、OAuth/PKCE、邮箱/文件夹/动作权限、令牌撤销，可视化连接配置；默认关闭 |
| 自定义规则 | 嵌套条件、优先级、版本、启停、模板、试运行；直接指向原邮箱文件夹 |
| 外部 AI 任务 | MCP 批次、租约去重、观察/执行、保护和限额、建议与冻结计划、记录；不内置模型；可选外部触发，使用统一任务记录 |
| 可选定时 | 每小时/每天/每周及时区、未来 5 次预览、持久化日程、漏跑合并；内置定时只运行固定规则，默认暂停观察 |
| Telegram | 加密 Bot Token、可视化检测/测试、按任务选择通知策略、独立投递队列与重试、相同故障 6 小时冷却 |
| 待后续实现 | CONDSTORE/QRESYNC、客户端私有规则导入、报告、在线密钥轮换 |

同步覆盖已添加邮箱的全部历史邮件元数据，默认自动发现全部可读取文件夹。已有实例升级时会切换为全部文件夹；新建连接时可选填写指定范围。点击「同步邮箱」会为所有已添加账号提交后台任务，最多两个账号同时处理，页面可查看进度；刷新或关闭页面不会取消任务。

每个文件夹先获取实际存在的 UID，再按最多 500 个编号分批读取（网易为 100 个），先写入暂存索引，整个文件夹成功后原子替换并保留仍有效邮件的随机引用；临时连接中断或超时会自动重连，最多重试两次，从失败批次继续；重连必须通过 UIDVALIDITY 校验，已提交的批次不重复写入。最终失败保留该文件夹原索引，其他已完成文件夹仍可搜索，页面显示失败阶段及原因。服务器重启后将未完成任务标为中断，可再次手动同步。手动任务完整扫描元数据；自动同步复用每个账号的常驻连接，仅为新 UID 读取元数据，已有邮件只读取 UID 和标记。UID 编号很大或缺少 UIDNEXT 时也按实际编号读取，不扫描空编号范围。

后台同步随服务启动，关闭浏览器也继续运行。支持 IDLE 的账号优先监控收件箱（没有收件箱时监控首个选定文件夹）；其他文件夹和推送遗漏由完整校对补齐。默认每轮完成后等 30 秒，可配置为 5–3600 秒。当前网易账号不支持 IDLE，实测 13 个文件夹增量校对约 11 秒，所以实际延迟为校对耗时加等待时间及网络延迟，不承诺零延迟；页面每 5 秒获取状态并在索引变化时刷新邮件列表。断线自动重连，服务重启自动恢复。文件夹显示名称跟随原邮箱，保留垃圾邮件、已删除、已发送及自定义归档名称；IMAP 保留名 INBOX 显示为“收件箱”。实际消失或带 IMAP 删除标记的邮件从索引移除。删除后后台分批归还空闲数据库页并释放可截断的 WAL，页内零散空间供后续索引复用。旧备份独立保留。

正文不持久化，附件不下载。日期使用 IMAP 接收时间（INTERNALDATE），搜索日期边界按北京时间（Asia/Shanghai）。在「邮箱连接」卡片点击「编辑配置」，可修改显示名称、邮箱地址、服务商、IMAP 主机、TLS 端口、同步文件夹及授权方式。默认保留当前授权，无需重新输入；也可替换授权码或切换外部 secret。修改名称或授权码保留已有索引；修改地址、服务商、主机或端口将清除旧本地索引，保存后自动连接并重建索引。缩小文件夹范围会立即移除范围外的本地索引。正在同步或排队的邮箱须等待任务结束后再保存修改，原邮箱邮件不受影响。

## 常用命令

在保存 `compose.yaml` 的目录定义辅助函数：

```bash
ma() { docker compose "$@"; }

# 状态、日志
ma ps
ma logs --tail 100 app

# 拉取并更新：保留数据
ma pull
ma up -d --no-build

# 恢复管理员：撤销所有会话，重置为新的临时凭据
ma exec app mail-auto bootstrap recover
ma exec app mail-auto bootstrap show

# 一致性数据库备份；目标文件必须不存在
ma exec app mail-auto backup /var/lib/mail-auto/data/backup-01.db
mkdir -p backups
ma cp app:/var/lib/mail-auto/data/backup-01.db ./backups/backup-01.db

# 停止服务并保留数据卷
ma down
```

默认数据卷 `mail-auto_mail-data` 保存 SQLite，`mail-auto_mail-keys` 保存独立 `master.key`。数据库备份**不包含主密钥**。完整恢复需要匹配的数据库和密钥；`ma down -v` 会删除两者，属于清空实例。详细备份、恢复和升级步骤见 [运维文档](docs/operations.md)。默认 Compose 项目名为 `mail-auto`，使用 `-p` 可另行指定。

## 从源码开发

固定 Go 1.27.3（漏洞扫描后采用的修复版本；Go 的自动工具链可下载所需版本）：

```bash
go run ./cmd/mail-auto
# 另一个终端查看凭据
go run ./cmd/mail-auto bootstrap show

make build
make check
# 可选漏洞扫描
go run golang.org/x/vuln/cmd/govulncheck@v1.9.0 ./...
```

直接运行源码时默认监听 `127.0.0.1:8080`，使用 `./data`、`./keys`，不读取环境变量。Go 二进制与内置前端单进程运行，无 Node 构建依赖。启动参数必须放在子命令前：

```bash
./bin/mail-auto --data-dir ./local-data --key-dir ./local-keys --listen 127.0.0.1:9000 serve
./bin/mail-auto --data-dir ./local-data --key-dir ./local-keys bootstrap show
```
