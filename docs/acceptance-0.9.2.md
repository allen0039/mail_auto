# 0.9.2 人工核验结案交付与验收

日期：2026-11-16。范围：管理员确认源、目标完整邮件一致，保留两份，持久阻止 Mail Auto 再次领取或执行整理写入。数据库 schema 13→14；不修改任务、每批数量、未读/星标保护或通知配置，不设置每日额度。

## 实现与验收边界

- 管理员会话和 CSRF 保护；预览与确认分别通过只读 EXAMINE、UID SEARCH 和 UID FETCH BODY.PEEK 读取完整邮件。校验 Message-ID、原计划位置、元数据、完整原文 SHA-256、字节数、前后标记及唯一性；预览十分钟过期。错误或变化保持待核验，不调用 MOVE/COPY/STORE/EXPUNGE。
- SQLite 原子保存结案证据、管理员、核验时间、原计划及原错误，原操作和任务的 `manual_kept` 与 `completed` 分开。没有目标 COPYUID 时继续保留空值，不能伪造成功移动。
- `manual_keep_blocks` 无到期时间且不依附会清理的历史记录；按同账号 ref、原物理位置或非空 Message-ID 拦截领取、计划执行与写入。重新索引、改规则、重启及普通清理仍保留保护；规则与任务预览同样显示人工保留保护。相同 Message-ID 的其他副本也会跳过。
- 保护适用于 Mail Auto 整理；用户、服务商和其他邮箱客户端仍可操作原邮箱。目录及 Message-ID 同时被外部改写后不能保证自动识别。暂不提供解除保护入口。
- schema 14 防止旧版本忽略保护：退回 0.9.1 及更早须恢复升级前数据库与密钥，见运维文档；旧版本不支持本保护，不能恢复后直接重放任务。

本地检查已通过：全套 Go race；补充改动后的人工结案/恢复/预览 race 回归；go vet、staticcheck、govulncheck（调用路径受影响漏洞为 0）；46 项发布核对测试；UI 全套 15 组（每个脚本在三种宽度运行）、新增结案 13 项/宽度、27 项 UI 门禁测试且无跳过；Compose、gofmt 和差异检查；两种架构镜像构建。

本地模拟测试不能替代原邮箱核验，也不能证明生产分类发生了写入。发布核对脚本只允许已知的 13→14 迁移，其他 schema 漂移仍拒绝；将 `manual_kept` 单列，不能用它作为自动分类成功的证据。
