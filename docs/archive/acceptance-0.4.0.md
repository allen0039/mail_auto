# 0.4.0 验收记录

日期：2026-10-23。构建、Go 测试、浏览器及部署位于 独立 Linux 环境，Mac 仅编辑源码/文档和查看虚构数据截图。本次不使用真实邮件试写，不创建真实业务任务，不发送真实 Telegram 消息。

## 已交付

- 可视化任务及 9 个 MCP 任务工具：仅手动、内置定时、外部 MCP；固定规则和外部 AI 两种引擎。新任务暂停观察，手动 AI 通过 MCP 显式 `manual=true` 单次运行。
- 固定规则无需模型；命中 AI 规则保留邮件并标明需要外部 AI。外部任务说明不假报客户端日程已建立。
- 受限内置身份、账号授权/有效期、版本失效、共享额度、邮件冲突和冻结计划/写后核验，三种触发复用原邮箱操作链路。
- 时区及未来 5 次预览、持久化下次运行、唯一发生键、重启租约、漏跑合并及可选外部逾期监测。逾期监测仅记录/提醒，不读取邮件或启动 AI。
- Telegram 加密配置、显式验证/测试、全局及每任务通知策略、运行/投递记录、独立 outbox、最多 5 次退避重试、429 等待、相同故障 6 小时冷却。

Telegram HTTP 在内存中完全拦截，任何真实网络投递都不可能发生。模拟提供商直接查询文件夹内容，不仅核对本地索引。首次浏览器脚本对空批次提交被拒绝，随后使用明确 AI 规则与单独保护设置的虚构邮件，产品无需放宽校验。截图发现静态版本号遗漏并已修正，最终重复页面闭环。

生产镜像在非 root、只读根目录及无网络隔离容器完成启动、健康、重启与引导凭据/密钥持久化检查。镜像基于旧生产运行时替换本次编译的静态二进制，依赖未新增。10 个只读 MCP 夹具评估问题在 `mcp-task-evaluation.xml`，仅定义评估集，未声称完成真实模型自动评测。

验证证据与运行日志应保存在私有发布记录中，不随公开仓库发布。

## 使用边界

每轮一个有界批次，默认 20、最多 50 封，最多扫描 500 条、10 分钟。更多候选在下一次触发继续断点；该实现明确收紧原计划的多页运行选择。任务使用账号全部启用规则；未提供备注、挑选部分规则、私有客户端标签/筛选定义导入或原生标签读写。

实际 Codex/ChatGPT 周期调度、OAuth 长期续期、无人值守确认和真实服务商写入仍需专用测试邮件验收。页面可生成调用说明，但不会自行创建外部周期任务。通知默认不含邮件内容，任务别名由用户自行避免敏感信息；网络应答丢失时 Telegram 可能重复投递。服务自身停机期间不能依靠自身通知。

## 备份与回退

升级前使用旧二进制生成 schema 6 一致性快照，并保存匹配密钥、旧 Compose、容器配置和私有比对基线；旧镜像应单独保留用于配套回退。

回退必须先停服务、另存当前库，再共同恢复升级前数据库、匹配密钥及旧 Compose/镜像。不能只换旧二进制打开 schema 7，也不能把备份写入仍运行的 WAL 数据库。具体备份路径和生产保留核对属于私有运维记录。

## 实际发布

本版本验证使用独立 Linux 测试环境和隔离模拟提供商，未公开生产地址、备份路径、实例标识或账号统计。schema 7、完整性检查、健康检查、非 root 和只读根文件系统验证通过；升级不会自动创建任务、开启写入或发送通知。

公开镜像为 `allen0039/mail-auto:0.4.0`，另提供 `latest`，支持 Linux amd64 / arm64。升级前请保存数据库快照、匹配主密钥、Compose 配置和旧镜像；回退不能只替换旧二进制打开 schema 7。
