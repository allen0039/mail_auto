# 0.8.6 验收记录：任务编辑与错误提示（轻量优化第二次交付）

范围：轻量优化方案“建议二”（简化任务编辑器）与“建议三”（任务保存、启用、运行的错误提示）。第一次交付与 LG-01 补修已由 Codex 在 0.8.5 验收通过。数据库仍为 schema 13，无迁移；没有新增框架、服务、依赖或接口。本文件不声明验收通过，交由 Codex 独立验收。

证据标记：**[模拟]** 隔离临时实例 + 假数据接口；**[本地后端]** Go 测试中的真实 HTTP 处理与 SQLite；**[生产只读]** Oracle1 只读查询；**[真实写入]** 原邮箱实际写入（本版没有）。

## 1. 实际改动与对应需求

后端代码：

- 新类型 `mail.TaskError{Code, Area, Target, Err}` 包装原有哨兵错误；`Error()` 与 `Unwrap()` 返回原错误，`errors.Is` 与错误文本不变，MCP、Agent 的行为不变。
- 包装点：
  - 保存时的授权检查（原就绪代码）、任务版本冲突、绑定规则版本变化（`rules_changed`）、任务数上限（`task_limit_reached`）。
  - 启用／暂停时的版本冲突。
  - 运行时的版本过旧：原来与 run_key 校验合并报 `invalid_input`，现单独报 `task_version_conflict`，状态仍为 400。
  - 运行时绑定规则变化。
  - 整理授权停用／到期／管理员变更：原为一个合并判断，拆成三个就绪代码，均仍为 403。
  - 授权源目录同步／读取问题。
- `operationError` 拆出 `operationStatus`，状态与消息逐项不变；仅三类任务接口的响应多出 `code`（以及 `area`、`target`）。

明确未实施：向导、新路由或设置页；草稿实时完整就绪 API；前端复制的权限判断；全站错误系统改写；自动重试；任何默认值、保存语义、授权范围或继承方式的变化；数据库迁移。

保持不变：草稿保护（保存中继续编辑、关闭询问、离开提示）、账号会话归属与异步响应保护、就绪判断、旧运行链接、模型连接与输出长度参数兼容、UI 门禁及 LG-01 修复。

`task-editor-ui-check.js` 共 53 项，每个宽度（1280 / 375 / 390）各跑一次，覆盖：

- 新任务：
  - 默认值；默认可见字段；折叠区包含的字段。
  - 日程与外部监测只在对应触发方式下显示。
  - 摘要无“自定义”；模式说明。
  - 保存按钮文案；POST 默认值（观察、暂停、固定规则、每批 20、保护、无历史起点、继承通知、全部规则、Asia/Shanghai）。
- 已有任务打开后原样保存：
  - 固定规则 + Cron + America/New_York + 绑定规则版本 + 自定义每批／历史／保护／通知，在折叠状态下提交。
  - 外部 AI + 外部触发 + 7200 秒监测。
  - 默认设置的内置定时 08:10。
  - 13 个字段与日程 6 个子字段逐项比较为 0 差异。
- 摘要准确：自定义项标记与“N 项自定义”；修改折叠区字段后摘要即时更新，折叠后照常提交。
- 折叠区校验：
  - 每批 0、超过授权上限、历史起点晚于今天：浏览器校验先展开，且不发请求。
  - 关闭浏览器校验时，页面检查展开、聚焦字段并说明原因。
- 保存失败：
  - `internal_not_allowed`：原因、去向、草稿与未保存标记保留、只发 1 次。
  - 笼统 `permission_denied`：不提具体缺口。
  - `invalid_input`：列出检查项并展开。
  - 未知代码：显示脱敏代码、不显示服务器原文；无代码显示 HTTP 状态；非法代码不回显。
  - 版本冲突：保留草稿、刷新列表、不重试。
  - `rules_changed`：给出可行下一步。
- 启用／暂停／运行失败：
  - `policy_disabled`：显示“打开整理授权”入口。
  - 版本冲突：刷新列表。
  - `rules_changed`：显示“编辑任务”入口。
  - 未知错误：兜底说明。
  - 成功后清除该任务的错误，其他任务的错误保留。
- 运行结果仍区分执行失败／写入待核验／没有可处理的邮件／观察完成。
- 异步与草稿：
  - 保存中继续编辑后失败：新编辑保留，错误显示在同一编辑器。
  - 旧保存失败在关闭并重新打开另一任务后返回：不改动新编辑器，改为提示。
  - A 邮箱的启用失败在切到 B 后返回：B 页面无错误，提示属于 A；切回 A 也不显示旧错误。
  - 仅展开／折叠不算修改；折叠区内的修改受关闭保护。
- 布局：编辑器在当前宽度无横向溢出。

## 3. 关键用例复现步骤

1. 准备检查环境：`npm i puppeteer-core`，然后 `PUPPETEER=<路径>/node_modules/puppeteer-core scripts/ui-check/run.sh scripts/ui-check/task-editor-ui-check.js`。
   - 检查在临时目录构建并启动隔离实例，使用一次性凭据，假接口，不连接邮箱。
   - 退出码 0 表示 3 个宽度共 159 项全部通过。
2. 人工复现“已有自定义任务原样保存”：
   1. 在任一临时实例中执行检查脚本第 1–2 段的假接口部分。
   2. 打开“自定义固定规则”：“更多设置”应已展开并显示“4 项自定义”。
   3. 手动折叠后点“保存修改”，检查 PUT 请求体与原任务相同。
3. 人工复现“版本冲突保留草稿”：
   1. 打开任务并修改名称。
   2. 让 PUT 返回 409 `task_version_conflict`。
   3. 编辑器保持打开，名称仍为修改后的值，列表刷新一次，没有第二次 PUT。
4. 后端代码：`go test ./internal/admin -run TestTaskErrorCodes -v`。
