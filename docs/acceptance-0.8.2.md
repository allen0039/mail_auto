## 2. S2-01 剩余问题

### 根因

0.8.1 只在两个位置检查归属：

- 响应返回时：`autoCurrent`。
- 两个设置表单提交时：`autoFormAccount`。

切换邮箱后、新邮箱的数据返回之前，还有三处没有保护：

- 页面上仍留着 A 的规则列表和任务列表。
- `rules.js` 和 `tasks.js` 的共享变量（`rules` / `policy` / `capabilities` / `tasks`）仍是 A 的缓存。
- `新建规则`、`新建任务` 只看“有没有选中邮箱”就启用。

列表按钮、编辑器和新建入口会直接用 A 的记录 ID 或 A 的授权缓存发出请求。响应时再检查已经来不及，因为写请求此时已经发出。

### 修改

- `app.js` 新增 `autoLoaded(mark)` 和 `autoRequire(mark, account)`，并提供加载中 / 加载失败两条提示文字。
  - 每个区域记录自己的数据是为哪次切换（`account` + `epoch`）加载的。
  - 同一邮箱刷新不改变 epoch，数据仍可用。
  - 切换邮箱后，旧记录不再满足条件。
- `automation.js` 的 `show()` 在切换时：
  - 把摘要、规则列表、任务列表、运行记录和外部批次替换为“正在加载所选邮箱…”。
  - 禁用两个“新建”按钮。
  - 关闭属于旧邮箱的编辑器、试运行、版本和任务详情对话框。
  - 摘要加载失败时显示“加载失败，请点‘刷新’重试”。
- `rules.js`：
  - 规则、授权、能力三者全部为当前切换加载成功后，才记录 `loaded` 并启用“新建规则”。
  - 外部批次单独记录 `runsLoaded`。
  - 加载失败时，列表显示失败提示，新建按钮保持禁用，重试成功后恢复。
  - 以下入口在发送请求或打开编辑器前调用 `autoRequire`，同时核对记录的 `account_id`：
    - 列表上的编辑、试运行、启停、创建任务、复制、版本。
    - 新建规则、规则编辑器保存。
    - 取消外部批次。
- `tasks.js`：
  - 任务、授权、规则、就绪全部为当前切换加载成功后，才记录 `loaded` 并启用“新建任务”。
  - 以下入口在发送前同样调用 `autoRequire` 并核对账号：
    - 任务卡上的全部按钮，包括修复入口、编辑、启停、手动运行、记录、详情、预览。
    - 运行记录中的继续处理、取消。
    - 新建任务、任务编辑器保存。
    - 规则“创建任务”（`createTaskFromRule`）。
  - `loadRuns` 在任务区尚未为当前邮箱加载时不读取，避免轮询定时器用 A 的任务去查运行记录。
  - 已发出的启停、运行、取消、继续请求，在页面切换后返回时只提示“属于原邮箱”，不改动当前页面。

按钮只在加载期间禁用；加载完成或重试成功后恢复，没有永久禁用。

### 回归：`ownership-ui-check.js` 新增 22 项（[模拟]，两邮箱版本号相同，A 每批 20、B 每批 8）

为了验证各处理函数自身的检查，而不只是靠“按钮被移出页面”，检查会把 A 的旧按钮重新插入页面后点击，并强制点击已禁用的“新建”按钮。

| 场景 | 结果 |
| --- | --- |
| B 全部延迟：旧列表移出、显示加载提示；新建按钮禁用；摘要不显示 A | 通过 |
| B 全部延迟：旧规则暂停、任务启用、手动运行、继续处理、取消外部批次 | 0 个请求，提示“正在加载” |
| B 全部延迟：新建 / 编辑规则与任务、规则创建任务 | 编辑器不打开，0 个请求 |
| B 加载完成 | 列表、摘要为 B，新建按钮恢复 |
| 加载后暂停规则 | `PUT /api/rules/r-a2`，`account_id=a2` |
| 加载后手动运行 | `POST /api/tasks/t-a2/run` |
| 加载后新建任务 | 预填每批 8，上限 8；保存为 `POST /api/tasks`，`account_id=a2`、`max_batch=8` |
| 加载后新建规则 | `POST /api/rules`，`account_id=a2` |
| 加载后规则创建任务 | 编辑器属于 B，上限 8 |
| 规则区先完成、任务区迟到 | 规则区可用；旧任务运行 / 启用 / 新建都不发送；B 的规则“创建任务”不使用 A 的任务授权缓存；任务随后完成后恢复 |
| 能力（规则区）迟到、任务区先完成 | 规则操作不发送、不打开；能力完成后恢复 |
| 任务加载失败 | 显示重试提示；运行 / 启用 / 新建仍被阻止；点“刷新”重试成功后，运行 B 的任务发出 `POST /api/tasks/t-a2/run` |
| A→B→A，两次加载都延迟 | A 先前的加载不算数，重新加载完成前不发送；B 迟到不覆盖 A；A 加载后运行 t-a1 |
| 已提交 A 的运行后切到 B | 请求仍为 t-a1；回调不改动 B 的页面，并提示属于“A邮箱” |

- 授权、文件夹表单的迟到响应，以及保存期间切换等原有场景（S2-01 第一部分），继续由同一文件的原有项覆盖，全部通过。
- 同一份 65 项检查在 v0.8.1 上：新增的 11 项“加载中”场景全部失败，随后脚本异常中止。说明这些检查能发现原缺陷。
