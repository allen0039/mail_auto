## 2. S2-01-R2

### 根因

0.8.2 只在规则试运行、版本历史**发起前**检查归属（`autoRequire`）。

- 请求返回后，代码直接改写共享的 `preview`、渲染内容并 `showModal()`。
- 切换邮箱时，`automation.js` 会关闭已打开的弹窗，但挡不住之后才返回的请求重新把弹窗打开。
- 试运行翻页取的是实时选择器的 `accountID()`，规则 ID 和 cursor 却还是旧预览的。

### 修改（`internal/admin/web/rules.js`）

- **会话（157–159 行）**
  - `viewSession(r)` 为每次试运行或历史查询创建会话，记录邮箱（`r.account_id`）、规则、当前切换代际 `autoScope.epoch`、cursor 和计数。
  - `viewLive(s, current)` 只在三个条件同时满足时为真：该会话仍是当前会话、邮箱与页面一致、epoch 未变。
  - 复用的是 0.8.1 引入的 `autoScope` 代际，没有另加机制。
- **试运行（160–170 行）**
  - `loadPreview(s, append)` 在发送前检查会话。翻页时还要求弹窗处于打开状态，否则提示“试运行已关闭或邮箱已切换”，不发送请求。
  - 请求体使用会话自己的 `account / ruleID / cursor`。
  - 响应返回后再次检查，会话不再有效就不渲染。
- **结束会话（171–175 行）**
  - 点关闭按钮或按 Esc（`cancel` 事件）会立即结束会话，不依赖异步排队的 close 事件。
  - 切换邮箱（包括 A→B→A）由 epoch 使旧会话失效。
  - 重新发起查询会替换会话。
- **打开弹窗（180–181 行）**
  - 试运行与历史只在会话仍有效时渲染并 `showModal()`。
