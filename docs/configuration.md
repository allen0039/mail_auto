# 配置与邮箱接入

## 部署配置

标准 Compose 无需配置文件、`.env` 或手工初始口令。可选配置参考 `deploy/config.example.yaml`；需要覆盖时：

1. 复制为 `deploy/config.yaml`。
2. 将 `deploy/compose.override.example.yaml` 复制为根目录 `compose.override.yaml`。
3. 调整文件，执行 `docker compose up -d`。

CLI 示例：`mail-auto --config /etc/mail-auto/config.yaml serve`。本地管理命令也须使用相同的目录或配置文件：`docker compose exec app mail-auto --config /etc/mail-auto/config.yaml bootstrap show`。

| YAML 字段 | 本地默认值 | 说明 |
| --- | --- | --- |
| listen | `127.0.0.1:8080` | 容器使用 `0.0.0.0:8080`；基础 Compose 映射宿主机回环端口 8080 |
| data_dir | `./data` | 数据目录；容器工作目录 `/var/lib/mail-auto` |
| key_dir | `./keys` | 独立密钥目录，与数据目录分开 |
| secret_dir | `/run/secrets` | 外部只读授权码目录 |
| public_url | 空 | 浏览器访问的精确 Origin，如 `https://mail.example.com`；不含路径 |
| secure_cookie | `false` | HTTPS 部署需设为 true；HTTPS public_url 会自动启用 |
| session_hours | `12` | 正常会话寿命，1–168 小时 |
| automatic_sync | `true` | 后台自动同步；CLI `--automatic-sync=false` 可关闭 |
| sync_interval_seconds | `30` | 每轮全部文件夹完成后的等待秒数，5–3600；CLI `--sync-interval-seconds` |
| retention_days | `0` | 兼容旧配置；接受 0–3650，但不再按日期过滤/删除邮件元数据，始终保留全历史 |

未知字段、额外 YAML 文档、无效 Origin、相同数据/密钥目录均报错。CLI 可覆盖 listen、data-dir、key-dir、secret-dir、public-url、secure-cookie、automatic-sync、sync-interval-seconds；不读取环境变量。启动和每小时仅清理过期会话与超过 90 天的审计记录，不会因邮件年代较早而删除索引。

## 邮箱接入

在管理页添加邮箱，使用邮箱服务商提供的 IMAP 客户端授权方式。各服务商开通界面可能变化，以其当前官方要求为准。

| 服务商 | 允许主机 | 端口与凭据 | 真实账号验收 |
| --- | --- | --- | --- |
| QQ | `imap.qq.com` | 默认 993/TLS，可自定义端口；开启 IMAP，通常使用客户端授权码 | 未验证 |
| 网易 | `imap.163.com`、`imap.126.com`、`imap.yeah.net` | 默认 993/TLS，可自定义端口；开启 IMAP，通常使用客户端授权码；支持能力协商后的 ID | 单个 163 账号 13 个文件夹、1,730 条元数据完整同步已验证 |
| iCloud | `imap.mail.me.com` | 默认 993/TLS，可自定义端口；通常需要 Apple 应用专用密码 | 未验证 |

v0.1.0 不允许自定义主机、IP 地址或明文 IMAP。其他域名、企业邮箱及服务商新别名需后续显式扩展白名单并测试。用户名填写服务商要求的邮箱登录地址。

文件夹默认留空，表示所有可读取文件夹（包括收件箱、已发送、归档，以及服务商允许读取的垃圾/已删除分类）。如只想读取部分分类，可在创建连接时每行指定一个名称。旧版已有连接升级时会切换为全部文件夹；授权码和账号不变。连接诊断仅列出文件夹，不同步邮件。中文文件夹由 IMAP 库处理 modified UTF-7。

全部历史邮件元数据分批读取，无日期或总封数截断。先通过 UID SEARCH 获取实际编号（该响应也受 32 MiB 预算限制），再每批读取最多 500 个 UID，网易为 100 个；不依赖 UIDNEXT，也不扫描空编号范围。32 MiB 响应预算和 45 秒网络截止时间按命令/批次重置，单命令限 45 秒，临时网络故障自动重连，单个操作最多执行三次，间隔 1 秒、2 秒；元数据从失败批次继续，丢弃该批未完整收到的数据，重连后 UIDVALIDITY 必须一致。授权失败、协议校验失败或本地写入失败不会重试；最终失败显示阶段与安全原因，不把半个文件夹发布为完整索引。

手动同步返回 HTTP 202 后在服务器后台执行，进度与终态持久化；最多两个账号同时处理，其余排队。刷新页面继续显示进度；关闭页面不会取消已提交任务。服务重启后未完成任务标为中断，需重新点击同步；自动同步会在重启后重新连接并继续校对索引；手动任务尚无跨重启的批次游标。已完成文件夹分别提交，失败文件夹保留原索引。

## 外部 secret

添加邮箱时，授权码与 secret 文件名只能选一个。示例 override 中启用 `qq_password` secret，并准备 `secrets/qq_password`；不要将该文件提交到 Git。容器用户 UID/GID 为 65532，文件必须对该用户可读。Linux 下可按实际权限选择所有者为 65532、模式 0400，避免世界可读；Compose 的本地文件 secret 通常保留宿主文件权限。

页面只填写 `qq_password`，不填写绝对路径。服务只允许 secret_dir 内的普通文件、单层文件名；拒绝路径穿越、逃出目录的符号链接、空文件和超过 4096 字节的内容。文件末尾换行会被去除。外部 secret 只读使用，不复制其明文到 SQLite，不回显，更新原文件后下次连接生效。

主密钥当前采用独立可写密钥卷生成和保存；本版未提供只读外部主密钥文件配置及在线密钥轮换，参见版本限制。

邮箱连接的新增和编辑表单均支持填写 TLS 端口（1–65535），已有连接会显示并预填实际保存的端口。连接使用直接 TLS，并验证服务器证书；请填写服务商提供的 IMAP TLS 端口。修改端口后请先运行连接诊断，再同步邮件。

## 后台自动同步

启动服务后，每个账号复用一个已认证 IMAP 连接。自动查询实际 UID 并校对所有现有 UID 的已读标记，仅为新 UID 获取完整元数据；删除和移动在完整成功的文件夹读取后更新。失败保留该文件夹原索引，不把暂存或不完整响应当作空文件夹。移入垃圾箱仍属于邮箱中的邮件，只有离开所选同步范围或被彻底删除才从该范围索引消失。手动操作优先，配置变更会取消旧监控并防止旧结果发布。

支持 IDLE 时，优先监控 INBOX（否则监控首个选定文件夹），通知后立即校对该文件夹；所有文件夹周期校对。服务器不支持或拒绝 IDLE 时自动降为周期校对。默认每轮完成后等 30 秒。**这不是严格实时或延迟上限**，还需加上 IMAP 读取、排队和网络耗时。当前网易账号未提供 IDLE，1,730 条现有索引的 13 文件夹校对实测约 11 秒，无旧邮件 ENVELOPE 重读。页面显示实际推送/校对/重连状态，每 5 秒更新。

断线后以 5、10、20、40、60 秒上限退避重连；失败的文件夹从当前已提交索引重新做增量校对。后台自动同步不会保存正文或附件。更改外部 secret 文件后，已连接会话在下一次重连时使用新内容。

## 回收站与存储空间

文件夹名称跟随邮箱端：垃圾邮件、已删除、已发送、自定义归档及嵌套路径保留原名称；仅将 IMAP 保留名 INBOX 显示为“收件箱”。列表、详情、筛选、账号范围、同步状态及诊断使用相同显示规则，请求和配置仍使用原始 IMAP 名称。回收站内未标记删除的邮件继续保留；实际消失或带 IMAP Deleted 标记的邮件从索引移除，恢复删除标记后可以重新同步。服务不会向邮箱发送删除、EXPUNGE 或清空回收站命令。

升级时旧 SQLite 库一次性转换为空闲页可渐进回收的格式，不更改业务 schema 和邮件随机引用。之后索引删除会通知后台分批回收数据库空闲整页，并尝试释放 WAL 文件；每分钟补查一次。数据库基础结构、仍有效记录及不足整页的可复用余量仍需空间；旧备份和容器日志独立保留，不随索引删除。无需手动频繁执行 VACUUM。

## 0.2.1 可视化 MCP 配置

进入「整理与 MCP」填写公开 HTTPS 地址并保存开关；配置保存在数据库中，无需重启。暂无域名可以留空并关闭。配置后可检测 HTTPS、OAuth 元数据和 MCP 认证入口，并复制 Codex 命令 / TOML 或 ChatGPT URL。HTTPS 反代由管理员另行配置。

首次启动且数据库尚无 MCP 设置时，`mcp_enabled` / `--mcp-enabled` 和 HTTPS `public_url` 可提供初值；在页面保存后，以数据库设置为准。CLI 中的 HTTP public-url 可继续作为当前管理入口，不阻碍后续通过页面保存 MCP 域名。变更 MCP 域名撤销已有客户端授权；旧数据库缺少 issuer 的 OAuth 授权需要重新连接。

远端整理由各账号的「允许整理原邮箱」独立控制，默认关闭。归档和回收站映射独立可选，普通文件夹分类不要求配置归档。启用时检查 UIDPLUS；仅探测能力不会移动邮件。详见 [MCP 接入指南](mcp-setup.md)。

## 可选整理任务与 Telegram（0.4.1）

任务、日程、运行和通知配置保存在 SQLite，通过「定时与任务」「TG 通知」管理；无需增加环境变量。任务默认跟随账号全部启用规则，也可绑定指定规则版本；规则版本变化会使相关运行失效。新任务暂停/观察，内置定时需管理员额外允许；外部模式等待已挂载 MCP 的实际客户端调用。Telegram Bot Token 使用独立主密钥加密，升级/恢复必须同时保留数据库和密钥卷。默认不开启任何任务或通知，详细配置见 [使用指南](automation-guide.md)。
