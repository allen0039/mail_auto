# 当前架构补充（0.3.0）

规则和外部 AI 批次复用现有原邮箱操作服务。`rules.go` 负责条件、优先级、未知字段、版本、循环检测及模拟；`automation_policy.go` 负责管理员授权；`automation.go` 负责领取租约、签名、跨客户端去重、结构化决定及观察/执行。后台同步只维护元数据，没有模型调用和独立整理调度循环。

schema 6 增加收信日期、星标、标记完整性和变化时间，以及规则/版本/授权/批次/领取/日额度表。外部 token 新增 rule_manage 和 automation；批次令牌不能通过原始 search/get/plan 绕过范围。提交、入队和实际写入复核权限、规则/策略版本；写入前通过 EXAMINE + FETCH 重新核对原邮箱元数据。Go 进程内自动化互斥锁先于账号锁获取，规则/策略更新与批次执行串行检查；数据库事务保证持久化及限额。原生标签尚未验证。

实际接口、限制和验证见 [使用指南](automation-guide.md) 与 [0.3.0 验收](acceptance-0.3.0.md)。以下保留 0.2.1 原邮箱与 MCP 基础说明。

Web 与 MCP 复用原邮箱文件夹服务：分类、归档、回收站、恢复都调用 IMAP 并核验实际位置；创建文件夹需要提供商 CREATE 后 LIST 确认，不发布本地替代分类。历史标签表保留，但不再暴露分类入口。

移动优先原生 UID MOVE；UIDPLUS-only 时顺序为 UID COPY → 保存精确 COPYUID → 独立只读连接核验目标 → 指定源 UID 标记 Deleted → UID EXPUNGE 指定源 UID → 核验源 UID（包括 Deleted）已消失且目标仍在。任何发出写入后的未知结果都不自动重试。绝不调用可能自动全局 EXPUNGE 的 Client.UidMove。只有可信目标映射才可重绑定稳定 ref。

管理员可视化 MCP 设置保存在 schema 5 的单行 mcp_settings；带版本控制防止并发覆盖。Server 使用不可变运行时快照，保存后切换处理器，无需重启；每个请求使用一致的公开地址。域名更换事务中撤销令牌并清理 OAuth 在途授权，授权载荷绑定 issuer，签发时再次核对运行时和管理员版本。会话、CSRF、原管理 Origin 及新的 HTTPS Origin 均按既有边界校验。MCP 开关和每账号写入开关独立，默认均关闭。

整理仍采用冻结预览、幂等异步任务、逐项状态、补偿和未知结果核验。OAuth 权限绑定邮箱、文件夹和动作（read、folder_manage、move、archive、trash、restore），每次请求与执行重查。无 AI API 调用。验证边界见 [0.2.1 验收](acceptance-0.2.1.md)，接入见 [MCP 指南](mcp-setup.md)。

以下为 0.1.0 历史基础，后续能力以上述说明和当前代码为准。

# 0.1.0 架构与扩展边界

```text
cmd/mail-auto          启动、版本、引导查看/恢复、一致性备份、健康检查
internal/config        严格 YAML、CLI 优先级与校验
internal/credentials   crypto/rand、Argon2id、AES-GCM、独立主密钥及外部 secret
internal/store         SQLite schema 2、WAL、事务、备份、清理、审计写入
internal/admin         HTTP 路由、会话、CSRF、初始化闸门、限流、嵌入式中文 UI
internal/mail          邮箱业务、白名单、连接限额、索引重建、分页搜索与随机引用
internal/imap          go-imap v1 只读适配、TLS、ID、EXAMINE、UID FETCH + PEEK
internal/mime          字符集、大小/深度/分段上限、纯文本与 HTML 转文本
```

管理员单用户，业务账号与 Web 管理员分离。服务端按数据库会话版本识别身份；首次受限会话只能确认身份、完成设置、退出，其他所有业务 API 统一拒绝。正式会话通过 `POST /api/settings/credentials` 验证当前密码后修改管理员用户名或密码。更新以当前版本及有效会话为条件，在同一事务中增加版本、撤销所有会话并写入审计；并发或已退出的旧会话不能覆盖新凭据。没有通过 MCP 接口读取管理配置的路径。

主密钥 32 字节，以受限权限写入独立卷，初始化使用完整落盘文件的原子 hard-link 发布；数据库存密钥指纹用于早期拒绝不匹配。临时引导记录加密存 SQLite，首次认证消费时事务删除；这不是安全擦除承诺，旧快照/WAL 仍须按敏感数据保护。账号凭据密文绑定账号 ID 为 AEAD 附加数据，防止密文跨账号置换。

SQLite 保存邮箱元数据，不缓存正文。每封邮件的远端身份为 account/folder/UIDVALIDITY/UID；对外暴露随机 ref。每次手动同步使用只读 EXAMINE、受响应预算限制的 UID SEARCH 和按实际 UID 集合的 FETCH 分批读取全历史元数据（每批最多 500 个，网易为 100 个），暂存至 sync_stage；一个文件夹全部成功后在数据库事务中发布，保留同 UIDVALIDITY+UID 的 ref，并移除远端已删除的邮件。临时网络超时或断线最多重连两次；在重新 EXAMINE 并核对 UIDVALIDITY 后重读失败批次，只有完整读取的批次才调用暂存回调，避免重复 UID。协议/身份校验与本地回调失败不重试。失败不发布暂存数据。多个文件夹分别提交；不声称全账号或全远端事务。sync_jobs 保存排队、运行、完成、失败及中断状态；最多两个账号并行。邮件元数据不再按年龄清理。适配器仅生成固定的安全错误类别，并保留底层 socket 错误类别以区分 go-imap 的笼统 connection closed；日志及持久化错误包含阶段、文件夹及进度，不包含服务端原始文本或邮件内容。

没有写入方法的 `mail.Remote` 接口隔离业务层与 IMAP；模拟 Remote 测试索引、权限和引用。协议集成测试使用真实 Go IMAP 服务器及内存邮箱，检查命令和未读状态，不把它当作真实服务商验收。

后续阶段在本业务层扩展：

- P2 进一步采用 CONDSTORE/QRESYNC 和更高效的服务商游标，保留全目录校对。
- P3 引入独立验证的 OAuth 资源服务器、主体与账号/文件夹权限；完成该路径前 `/mcp` 保持不可用。Web Cookie 不作为 MCP 令牌。
- P4 添加本地预授权、操作计划、预览、限额及不确定结果核验，避免在只读接口中混入写入。
- P5 模型 Provider、有限结构输出、来源引用、持久任务、预算与快速停用。邮件与模型输出始终是业务数据，不能授予权限。

初始版本没有创建空的 MCP、AI、任务包或假报告页面。新增能力必须同步补充后端策略、测试和真实联调记录。

自动同步由服务生命周期内的 supervisor 管理，账号新增、编辑、移除自动启动/取消监控，每账号一个常驻认证连接。连接中的增量读取与前台远端读取共享两个批量读取名额；空闲连接不占名额，最多随账号数保留 10 个空闲连接。配置事务不占远端读取名额，前台操作通过账号 epoch 使在途后台结果失效。发布前持服务互斥锁，在同一数据库事务内比较完整账号配置和 epoch，防止旧凭据、旧范围或手动同步前的结果覆盖新索引。

自动读取的 UID+FLAGS 清单与新邮件暂存必须完整成功，才事务性校正删除、已读状态和新增元数据。UIDVALIDITY 变化重新读取该文件夹元数据并更换引用。IDLE 命令使用独立响应 handler 接收并合并通知，避免客户端 Updates 字段并发赋值和推送突发阻塞；每 25 秒内结束/续订，以遵守 45 秒命令截止时间。无 IDLE 或服务器拒绝时使用周期校对；当前选中的一个文件夹可推送，其余仍周期校对。配置间隔是完成一轮后的等待，非延迟保证。状态与索引 revision 供页面每 5 秒获取，revision 不变时不重查列表或重建账号卡片。

文件夹显示与 IMAP 身份分离：搜索/读取 API 保留原始 folder，folder_label 供显示；仅将 IMAP 保留名 INBOX（不区分大小写）显示为“收件箱”，其他名称包括垃圾邮件、已删除、自定义归档与嵌套路径全部保留。前端列表、筛选、详情、诊断及同步状态遵守同一规则，不合并不同名称的分类。同步使用 UID SEARCH UNDELETED，并再次检查 FETCH 中的 \\Deleted，防止查询与读取之间删除造成残留。服务器 EXISTS 总数与可见 UID 数分别保存，避免含删除标记的文件夹持续触发虚假 IDLE 变化。

SQLite 在旧库首次打开时一次性转换为 auto_vacuum=INCREMENTAL（需要一次 VACUUM，业务 schema 仍为 2），并开启 secure_delete。删除索引、移除账号/范围及清理暂存后通知维护协程；每次最多回收 256 个空闲页，仍有空闲页则继续分批，成功后截断 WAL。每分钟补做维护，外部读锁等暂时阻碍时后续重试。单次常规回收设置 3 秒上下文超时，前台与同步仍通过单数据库连接串行访问。只归还完整空闲页，页内余量继续复用；不保证每删一条记录立即缩小文件，也不是磁盘介质/旧备份的安全擦除承诺。
